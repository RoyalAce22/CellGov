# System software

Boot-frontier matrix for the software that ships inside every PS3
firmware image, measured firmware by firmware. Each row records the
same two verdicts the [title matrix](titles.md) does -- did CellGov
reach the same architectural state as RPCS3 at the checkpoint
(Convergence), and is that state byte-identical modulo classified
non-semantic divergences (Byte parity) -- for one firmware version.

The system software is not a title. A game states the firmware it
shipped against in its own `PARAM.SFO`, and that floor is the one
cell its headline row is measured at. The software here ships in
every firmware image, so it has no floor of its own: its version axis
*is* the firmware axis, and every firmware version its manifest
declares is a row of equal standing. That is why it has a page of its
own rather than a row on the title index, where a `Year` or a
`Config` column would mean something different from every other row.

Read the Convergence and Byte parity columns through
[concepts/](concepts/README.md), the same way as on the title matrix.

Column definitions:

- **Serial**: registry key, linking to the per-cell page.
- **Config**: the firmware version the row was measured at.
- **Checkpoint**: the deterministic boot stopping point, and the
  outcome the boot reached there.
- **Steps**: unit yields at the default per-step budget (256
  instructions).
- **Insns**: rough instruction count to checkpoint (`steps * budget`).
- **Convergence**: did CellGov reach the same architectural state
  as RPCS3?
- **Byte parity**: byte-level agreement at that state.
